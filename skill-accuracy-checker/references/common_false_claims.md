# 常见虚假声称模式及修复方案

本文档列出技能描述中常见的虚假声称模式，以及推荐的修复方案。

## 1. 数量声称不实

### 模式 1: 夸大的数量
**虚假示例**:
- ❌ "193 个即插即用的 AI 专家角色"
- ❌ "72 个设计系统"
- ❌ "31 种设计原型"

**实际检查**: 目录为空或文件数量远少于声称

**修复方案**:
```
✅ "AI 专家角色库框架 - 实际角色文件需单独安装"
✅ "设计系统框架 - 提供 X 个示例"
✅ "支持多种设计原型（需配置）"
```

### 模式 2: 不存在的功能数量
**虚假示例**:
- ❌ "支持 50+ 种数据格式"
- ❌ "内置 100+ 个模板"

**修复方案**:
```
✅ "支持主流数据格式（CSV, JSON, XML 等）"
✅ "提供多种模板（具体数量视安装情况而定）"
```

## 2. 功能声称不实

### 模式 3: 声称的功能不存在
**虚假示例**:
- ❌ "支持自动部署到 AWS/GCP/Azure"
- ❌ "内置 AI 图像识别功能"

**实际检查**: `scripts/` 目录中没有相关脚本，描述的功能未实现

**修复方案**:
```
✅ "支持手动部署指南"
✅ "可集成 AI 图像识别 API（需配置）"
```

### 模式 4: 过时的功能描述
**虚假示例**:
- ❌ "支持 Python 2.7+"
- ❌ "兼容 Windows 7+"

**实际**: 代码已不支持旧版本

**修复方案**:
```
✅ "支持 Python 3.8+"
✅ "兼容 Windows 10+, macOS 10.15+, Linux"
```

## 3. 引用错误

### 模式 5: 引用不存在的技能
**虚假示例**:
```
集成以下技能:
- skill-a (不存在)
- skill-b (不存在)
- skill-c (存在)
```

**修复方案**:
```markdown
集成以下技能:
- skill-c (存在)

待集成:
- skill-a (计划中)
- skill-b (计划中)
```

### 模式 6: 错误的文件路径
**虚假示例**:
```bash
python scripts/process.py  # 文件实际是 process_data.py
```

**修复方案**:
```bash
python scripts/process_data.py  # 修正文件名
```

## 4. 版本号错误

### 模式 7: 过时的版本声称
**虚假示例**:
- ❌ "兼容 TensorFlow 1.x"
- ❌ "基于 React 16"

**实际**: 代码已升级到新版本

**修复方案**:
```
✅ "兼容 TensorFlow 2.x"
✅ "基于 React 18+"
```

## 5. 模糊或误导性描述

### 模式 8: 夸大兼容性
**虚假示例**:
- ❌ "支持所有主流浏览器"
- ❌ "跨平台完美运行"

**修复方案**:
```
✅ "支持 Chrome, Firefox, Safari (最新版本)"
✅ "支持 Windows, macOS, Linux (部分功能可能受限)"
```

### 模式 9: 隐藏限制
**虚假示例**:
- ❌ "无限免费使用" (实际有配额限制)
- ❌ "完全自动化" (实际需要手动配置)

**修复方案**:
```
✅ "免费使用 (每月 100 次 API 调用)"
✅ "半自动化 (需要初始配置)"
```

## 自动检测规则

### 正则表达式模式

```python
# 检测数字 + 量词
patterns = [
    r'\d+\s*个\s*[^\s\d]{1,4}',  # 193个专家
    r'\d+\s*种\s*[^\s\d]{1,4}',  # 31种设计
    r'\d+\s*款\s*[^\s\d]{1,4}',
    r'\d+\s*台\s*[^\s\d]{1,4}',
    r'\d+\s*套\s*[^\s\d]{1,4}',
]

# 检测夸大词
exaggerations = [
    '所有', '全部', '无限', '完美', '完全',
    '最', '第一', '唯一', '100%'
]
```

### 验证检查清单

- [ ] 数字声称是否有实际文件/目录支持？
- [ ] 功能列表是否都能在 `scripts/` 或 `references/` 中找到对应实现？
- [ ] 引用的技能是否都存在于 `~/.workbuddy/skills/`？
- [ ] 文件路径是否正确？
- [ ] 版本号是否与实际代码一致？
- [ ] 是否有隐藏的限制或前提条件未说明？

## 修复模板

### 模板 1: 数量声称 → 框架描述
```
BEFORE: "X 个 YYY"
AFTER:  "YYY 框架 - 提供基础结构，具体 YYY 需单独配置"
```

### 模板 2: 不存在的功能 → 计划功能
```
BEFORE: "支持 XXX 功能"
AFTER:  "计划支持 XXX 功能 (当前版本不支持)"
```

### 模板 3: 夸大描述 → 准确描述
```
BEFORE: "完美支持所有平台"
AFTER:  "支持主流平台 (Windows, macOS, Linux)"
```

## 使用建议

1. **创建技能后立即验证** - 不要等用户发现问题
2. **定期检查已发布的技能** - 功能会变化，描述可能过时
3. **使用脚本自动化** - 运行 `scripts/verify_counts.py` 自动检测
4. **诚实描述** - 宁可少说，不要夸大
5. **标注限制** - 明确说明前提条件和限制
